# Embeddings Quality — задача и реализация

Статус: первая версия реализована и проверена, 2 октября 2026.

## Цель

Проверить, разделимы ли классы дефектов поверхности металла в исходном
пространстве эмбеддингов SSL-модели. Основной сценарий: bbox-level SimCLR,
resize + padding до 512×512, выгрузка из Qdrant в массивы NumPy.

Источник требований: **последний ответ** в
[чате об анализе эмбеддингов](https://chatgpt.com/share/6abf4204-e048-83ed-8558-af4ccb34e2f0).
Уточнение пользователя: нужен пакет именно для оценки исходного пространства.
Пользователь подтвердил вход: экспорт Qdrant с преобразованием в NumPy.

## Принятые решения

- Python-пакет `embeddings-quality`, импорт `embeddings_quality`, API и CLI.
- Вход: `embeddings (N, D)`, `labels (N,)`; необязательные ID, группы и метаданные.
- Исходная размерность D сохраняется. По умолчанию L2 + cosine;
  для исходных координат доступен euclidean без нормализации.
- Локальная геометрия, линейная разделимость и nuisance-факторы оцениваются отдельно.
- Геометрия: purity @ 5/10/20/50, baseline/lift с учётом дисбаланса,
  silhouette по объектам и классам, d_positive/d_negative/margin.
- Предсказуемость: multiclass LogReg и kNN с OOF predictions, dummy baseline,
  balanced accuracy/macro-F1, confusion matrix; попарные линейные probes
  с ROC-AUC и balanced accuracy.
- При наличии image_id/coil_id/batch_id используется StratifiedGroupKFold;
  same-group neighbors по умолчанию исключаются из purity/margin.
- Nuisance probes: RF regression для числовых и линейная классификация
  для категориальных метаданных; оценки только на validation.
- Неопределённые метрики и невозможные folds явно отражаются в отчёте.
- Выход: JSON, CSV, Markdown, необязательная SVG-матрица, очередь ручного просмотра.
- Расстояния считаются точно блоками. Время квадратично по N;
  для больших экспортов нужна зафиксированная репрезентативная выборка.

## Объём первой версии

Реализован аудит готовых frozen features и single-label разметки.
Кластеризацию с PCA/UMAP из исходного ответа не включаем в оценку разделимости:
она меняет анализируемое пространство. Обучение SSL, извлечение признаков,
изменение разметки и автоматическое удаление объектов требуют отдельной задачи.
Cleanlab уже применён в исходном эксперименте; его scores можно сопоставлять
с `samples.csv` по ID в следующем исследовании.

## Критерии готовности

- Устанавливаемый пакет с API и CLI, документация для NumPy из Qdrant.
- Основные метрики используют исходные координаты и сохраняют D.
- Контроль на разделённых классах и случайных метках.
- Проверка группового split на повторяющихся кропах без group leakage.
- Сверка silhouette и локальных расстояний с независимым расчётом.
- Обработка singleton-классов, больших k, дубликатов и плохих входов.
- Читаемый отчёт со статусами пропусков, параметрами и ограничениями выводов.

## Дальнейший эксперимент на данных пользователя

1. Выгрузить одинаковый набор объектов, метки и ID источников в NumPy.
2. Запустить API; при наличии bbox/padding metadata включить nuisance probes.
3. Оценить OOF linear/kNN scores, baseline и попарную матрицу.
4. Посмотреть purity/lift и квантили silhouette/margin по классам.
5. Проверить трудные пары и объекты из review_queue вручную.
6. Сравнить representation/preprocessing на тех же объектах и группах.

Качество конкретной SSL-модели пока не измерено: реальные эмбеддинги в workspace
не предоставлены. Запуск и интерпретация описаны в [README.md](README.md).

## Результаты проверки

Для эксперимента с DINOv3 добавлен отдельный пакет `../dinov3-embedder`:
изображения + bbox (COCO/CSV) → frozen ViT features → совместимый NPZ
с ID/метками/группами и метаданными preprocessing. Проверка качества
предобученного DINOv3 на реальных объектах остаётся следующим экспериментом.

- 33 теста прошли: геометрия, CV, nuisance probes, экспорт, CLI и крайние случаи.
- Wheel и source distribution собраны; wheel установлен в временное окружение.
- CLI из установленного wheel создаёт CSV/JSON/Markdown/SVG.
- Демонстрация на 512D: linear OOF balanced accuracy = 1.000 для разделённых
  классов и 0.289 для перемешанных меток при случайном уровне 1/3.
- Использованы Python 3.12, NumPy 2.5.3, pandas 3.0.6, scikit-learn 1.9.1.
